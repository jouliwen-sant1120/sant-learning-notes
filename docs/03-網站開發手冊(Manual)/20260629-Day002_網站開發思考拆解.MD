# 20260629-Day002_網站開發思考拆解

## 今日目標

不是繼續開發網站，而是重新拆解網站開發流程，理解每一步存在的原因，建立共同語言與共同思考方式。

---

# 今日討論重點

## 1. 建立共同語言的重要性

今天確認：

真正影響 AI 協作效率的，不是 Prompt，而是共同語言。

如果彼此對同一個名詞有不同理解，即使 AI 很強，也容易一直重工。

因此決定：

* 新名詞先定義，再討論。
* 中文優先，再補英文。
* 以白話方式理解，不急著學技術。

---

## 2. 網站開發流程重新拆解

重新回顧 Day001 的流程：

1. 利用 AI 協助完成《個人品牌.md》
2. 利用 AI 協助完成《網站藍圖.md》
3. 建立網站開發環境（VS Code、Git、GitHub）

「為什麼需要這一步？」

「怎麼做。」

---

## 3. 今日理解的重要觀念

### 《個人品牌.md》

目的：

不是限制自己，而是先確認目前網站的定位。

可以隨著品牌成長持續更新。

---

### 《網站藍圖.md》

目的：

不是畫網站版面，而是整理網站要回答哪些問題。

例如：

* 我是誰？
* 我分享什麼？
* 我能幫助誰？
* 如何聯絡我？

---

## 4. VS Code 的重新定位

今天最大的收穫：

VS Code 並不是網站工具。

也不是 Python 工具。

它比較像：

> **一間創作者的工作室。**

不同的專案，只是把不同工具搬進同一間工作室。

例如：

* Python 專案
* 網站專案
* Markdown 文件
* AI 開發專案

VS Code 本身不決定要做什麼，而是提供一個開發與整理專案的空間。

---

## 5. 今日學習方式確認

確認自己的學習偏好：

* 偏向架構式理解。
* 偏向視覺化思考。
* 喜歡先理解整體，再深入細節。
* 不喜歡直接記憶大量英文名詞。

因此，後續網站教學將採用：

1. 建立共同語言。
2. 畫出整體架構。
3. 解釋角色定位。
4. 最後才進入技術細節。

---

# 今日心得

今天最大的收穫，不是學會 VS Code。

而是理解：

每一個工具都有自己的角色。

真正重要的是知道：

它為什麼存在？

它解決什麼問題？

它與其他工具如何合作？

而不是急著學會所有操作。
