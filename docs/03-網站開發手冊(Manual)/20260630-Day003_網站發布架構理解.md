# 20260630-Day003_網站發布架構理解

## 今日目標

理解網站從建立到公開的整體流程。

本次不學操作，而是理解各工具在網站開發中的角色與彼此關係。

---

# 今日討論主題

## 一、VS Code 的角色再次確認

今日重新確認：

VS Code 並不是網站工具。

它是一個：

> **開發工作室 (Development Workspace)**

可用來：

- 撰寫網站
- 撰寫 Python
- 撰寫 Markdown
- 撰寫 SQL
- 管理專案

VS Code 本身並沒有網站功能。

真正決定用途的是：

「今天放入什麼專案」。

---

## 二、GitHub 的角色

目前共識：

GitHub 可先理解成：

> **專案雲端倉庫 (Repository Hosting Platform)**

主要用途：

- 保存專案
- 管理版本
- 維護程式
- 團隊協作

GitHub 並不是網站。

也不是網站展示平台。

---

## 三、Repository 的理解

目前理解：

一個 Repository = 一個完整專案。

例如：

- Jou-Website
- Jou-PowerBI
- Jou-Python
- Jou-Excel
- Jou-AI

每個專案彼此獨立。

互不影響。

---

## 四、GitHub Pages 的角色

今日最大的收穫：

GitHub Pages 並不是另一個 Repository。

也不是 GitHub 裡的一個資料夾。

它是：

> **GitHub 提供的網站發布服務 (Static Website Hosting)。**

作用：

將 Repository 發布成公開網站。

流程：

VS Code

↓

GitHub Repository

↓

GitHub Pages

↓

公開網址

例如：

https://帳號.github.io/Jou-Website/

---

## 五、網站發布流程

目前理解：

網站完成後：

先放入 GitHub Repository。

若需要公開展示：

再啟用 GitHub Pages。

因此：

GitHub Pages 負責：

> **讓全世界可以瀏覽網站。**

---

## 六、目前網站架構再次確認

目前採用：

入口網站（Portal）

↓

Power BI Showcase

↓

Python Showcase

↓

Excel Showcase

↓

AI Showcase

各 Showcase：

皆為獨立 Repository。

個人品牌網站：

只負責入口與整合。

---

## 七、本日最大的理解

今天最大的收穫不是學會 GitHub Pages。

而是理解：

每個工具都有自己的角色。

VS Code：

負責製作。

GitHub：

負責保存。

GitHub Pages：

負責發布。

每個工具各司其職。

---

# 今日心得

今天重新建立了網站發布流程的完整概念。

開始理解：

網站不是做好就能被別人看見。

而是需要：

建立 → 保存 → 發布

三個不同階段。

也理解：

GitHub Pages 並不是新的網站，

而是將 Repository 發布成真正可公開瀏覽的網站。
