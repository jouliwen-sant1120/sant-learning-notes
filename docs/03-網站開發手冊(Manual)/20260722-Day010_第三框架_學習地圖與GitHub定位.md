# 三、卡片管理原則

-   首頁卡片採動態擴充。
-   新主題先放入「其它」。
-   當內容累積成熟，再獨立成首頁卡片。
-   首頁以 Category 概念設計，不將分類寫死於程式。

------------------------------------------------------------------------

# 四、GitHub 定位

討論後正式採用：

**方法二：GitHub 不直接作為首頁分類，而是各分類頁面的作品來源。**

流程：

首頁 → 學習地圖 → 各主題專區 → GitHub Repository（作品來源）

網站負責：

-   知識整理
-   學習分享
-   閱讀體驗
-   個人品牌展示

GitHub 負責：

-   原始專案
-   程式碼
-   版本管理
-   下載資源

------------------------------------------------------------------------

# 五、GitHub 公開策略

初步共識：

-   網站可公開。
-   Repository 視專案性質決定 Public 或 Private。
-   公司相關專案維持 Private。
-   個人作品與學習成果再評估是否公開。
