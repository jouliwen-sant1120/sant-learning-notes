Sant 個人品牌網站文件管理策略

---

# 背景

建立網站初期，討論 docs 資料夾應如何規劃，並確認各類 Markdown 文件的角色與定位。

---

# 討論重點

## 一、是否每個資料夾只能有一個 Markdown？

結論：

否。

依文件性質決定。

* 核心文件：一份主文件。
* 紀錄文件：可建立多份 Markdown。

---

## 二、Blueprint 的定位

Blueprint 為網站最高規劃文件。

內容包含：

* 品牌定位
* 網站使命
* 頁面規劃
* MVP 範圍

屬於專案的長期規劃文件。

---

## 三、Constitution 的定位

原規劃直接建立 Version 1.0。

討論後決定：

先建立 Draft v0.5。

待網站 MVP 完成後，再依實際開發經驗整理正式版本。

原因：

最佳實務應來自實作，而非事前假設。

---

## 四、Manual 的定位

重新定義為：

Project Journal（專案日誌）

採每日紀錄方式。

記錄：

* 今日完成事項
* 今日決策
* 今日學習
* 下一步

---

## 五、Chat History 的定位

保存 AI 討論過程。

保留：

* 思考脈絡
* 架構討論
* 決策理由
* 問題分析

作為未來回顧的重要參考。

---

# 今日重要觀念

Blueprint 定義方向。

Manual 記錄現在。

Chat History 保存思考。

Constitution 整理最佳實務。

四者共同形成完整的專案知識管理架構。

---

# 今日結論

正式採用 docs 作為 Sant 專案知識庫（Project Knowledge Base）。

未來所有重要決策皆以 Markdown 文件保存。
